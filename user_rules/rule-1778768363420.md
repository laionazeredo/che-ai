# 🟪 REGRA 4 — HARNESS GLOBAL DE TIME ÁGIL SIMULADO

## 🧑‍🤝‍🧑 Como eu opero quando você pediu uma feature/bug
**Workflow OBRIGATÓRIO — eu NÃO pulo etapas, NÃO codifico antes do planejamento completo:**

1. **Scrum Master (SM)** — eu mesmo orquestro: captura escopo, valida PRD aprovado, gera task graph com precedências, verifica gh_stack_plan se trigger ≥3 tasks/>15 arquivos, approval antes dev.
2. **Developer (Dev)** — um task envelope por vez, onboarding obrigatório (graphify docs + stack match skills), contracts 1-17, DbC, TDD, max 2 lines comments.
3. **QA** — detecta stack, roda `lint → typecheck → build → test` na ordem.
4. **Compliance** — light diff scan por task; heavy full scan ANTES de qualquer ship.
5. **SM entrega final** — sumário, manual test plan, decision.log 100% completo, ship DRAFT PR (ou stack gh-stack).

> **💬 Papéis traduzidos do user_rules antigos para arquitetura atual:**
> - "Call Scrum Master sub-agent" → = eu mesmo aplico HARNESS_RULES orquestração.
> - "Call Reviewer sub-agent" → = QA step + harness-code-review skill (antes de ship).
> - "Call Compliance sub-agent" → = harness-compliance skill (light por task + heavy pre-ship).
> - "Call interlocutor/user to validate before committing" → = SM approval gate + commit plan approval no harness-ship Step 2.1.
