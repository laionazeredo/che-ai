- Iterativo por tasks : ao seguir uma WBS/tasks.md, execute uma task por vez , respeite precedências e, ao concluir cada task, pare e me chame para revisar/aprovar antes de seguir.
- Worktrees primeiro : se eu não indicar explicitamente o worktree/caminho, pare e peça a referência antes de fazer qualquer alteração.
- Arquitetura (onion/clean) : mantenha dependências de dentro para fora ; domínio isolado; fronteiras claras entre domínio (tipos/entities/use cases) e integrações (DB/APIs/framework).
- Contrato → teste → implementação (TDD) :
- defina tipos/contratos primeiro;
- escreva teste unitário para o contrato;
- só então implemente produção;
- sempre siga o padrão de testes existente no contexto do repo.
- TypeScript forte :
- prefira unknown a any ;
- valide e tipe dados de fora do sistema (DB, APIs, mensagens);
- use type guards, Record , utility types e satisfies quando ajudarem a manter o contrato correto.
- Design de funções/módulos :
- funções e módulos pequenos; segregação de interfaces;
- prefira funções puras e dependências explícitas por argumento;
- limite a 1–2 argumentos; se precisar, use input / options tipados;
- prefira retornar um resultado (evite void quando houver alternativa).
- Erros e controle de fluxo :
- defina caminhos de erro desde o contrato;
- prefira early return e função “flat”;
- evite throw quando houver resposta razoável (defaults/empty), use throw só para estados realmente irrecuperáveis.
- Qualidade antes de entregar :
- execute o comando definido no repo para lint/format antes de finalizar;
- verifique e corrija Diagnostics/Problems para os arquivos tocados;
- ao rodar Nx, sempre adicione --tui false .
