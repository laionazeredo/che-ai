- Iterative by tasks: when following a WBS/tasks.md, execute one task at a time, respect precedence, and upon completing each task, stop and call me for review/approval before proceeding.

- Worktrees first: if I don't explicitly indicate the worktree/path, stop and ask for the reference before making any changes.

- Architecture (onion/clean): keep dependencies from the inside out; isolated domain; clear boundaries between domain (types/entities/use cases) and integrations (DB/APIs/framework).

- Contract → test → implementation (TDD):
- define types/contracts first;
- write unit tests for the contract;
- only then implement production;
- always follow the existing testing pattern in the repo context.

- Strong TypeScript:
- prefer unknown to any;
- validate and type data from outside the system (DB, APIs, messages);

- Use type guards, Record, utility types, and satisfies when they help maintain the correct contract.

- Function/Module Design:
- Small functions and modules; segregation of interfaces;

- Prefer pure functions and explicit dependencies per argument;

- Limit to 1–2 arguments; if necessary, use typed input/options;

- Prefer returning a result (avoid void when there is an alternative).

- Errors and Flow Control:

- Define error paths from the contract;

- Prefer early return and "flat" functions;

- Avoid throw when there is a reasonable response (defaults/empty), use throw only for truly unrecoverable states.

- Quality Before Delivery:

- Execute the command defined in the repo for lint/format before finalizing;

- Check and correct Diagnostics/Problems for the files touched;
