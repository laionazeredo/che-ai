## 🧪 TDD Rigoroso
1. **Define types/contracts PRIMEIRO.**
2. **Escreve unit tests do contract ANTES.**
3. Só depois implementa produção.
4. Segue SEMPRE o padrão de testes EXISTENTE no repo context (não inventa framework novo).

## 🔷 TypeScript Forte
- Prefer `unknown` a `any`.
- Valida + tipa dados vindos de FORA do sistema (DB, APIs, mensagens, user input).
- Usa type guards, `Record`, utility types, `satisfies` onde ajuda manter contrato correto.
