- Validação em borda : normalize/valide inputs logo no início; depois mantenha o core do algoritmo simples e declarativo.
- Estilo declarativo : prefira map / filter / reduce / sort e imutabilidade; evite loops mutáveis quando piorarem a legibilidade; evite recursão profunda.
- Logging consistente :
- use o logger do contexto (nunca console.* por padrão);
- info para início/fim de fluxo, debug para inputs/decisões importantes, warn para estados tratados, error para estados irrecuperáveis;
- não logue secrets/PII.
- Mudança de comportamento = teste primeiro : antes de alterar código existente, escreva um teste que capture o comportamento desejado; se não existir framework/padrão claro no repo, peça orientação.
