- Edge validation: normalize/validate inputs right at the beginning; then keep the core of the algorithm simple and declarative.

- Declarative style: prefer map / filter / reduce / sort and immutability; avoid mutable loops when they worsen readability; avoid deep recursion.

- Consistent logging:
- use the context logger (never console.* by default);
- info for start/end of flow, debug for important inputs/decisions, warn for handled states, error for unrecoverable states;
- do not log secrets/PII.

- Behavior change = test first: before changing existing code, write a test that captures the desired behavior; if there is no clear framework/pattern in the repo, ask for guidance.
