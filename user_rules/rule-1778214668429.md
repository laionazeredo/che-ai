# 🟨 REGRA 3 — DESIGN DE CÓDIGO + LOGGING + COMPORTAMENTO

## 🎯 Validação de Edge (input hygiene)
- **Normalize / valide TODOS os inputs LOGO NO INÍCIO** (precondition contracts).
- Depois que a validação passa, core do algoritmo fica simples e declarativo.

## 📐 Estilo Declarativo
- Preferência estrita: `map / filter / reduce / sort` + **imutabilidade**.
- Evita loops mutáveis quando pioram legibilidade.
- Evita recursão profunda.

## ✏️ Design de Funções/Módulos (contracts §7 + §13)
- Funções e módulos pequenos; segregação de interfaces.
- Funções puras + dependências explícitas por argumento.
- Máximo 1–2 argumentos; se necessário, use **typed input/options** objeto.
- Retorna **Result/Option-style** sempre que possível. Evita `void` quando tem alternativa.

## 🚦 Controle de Fluxo + Erros
- Define error paths a partir do contract.
- **Early return + funções flat** (evita aninhamento profundo de if).
- Usa `throw` SOMENTE para estados verdadeiramente irrecuperáveis; se há resposta razoável, retorna default/empty/handled state.

## 📝 Logging Consistente (contracts §8)
- **NUNCA `console.*` por padrão.** Usa context logger estruturado do projeto.
- Níveis:
  - `info` = start/end de fluxo macro
  - `debug` = inputs/decisões relevantes
  - `warn` = estados tratados mas não esperados
  - `error` = irrecuperável
- **NUNCA loga secrets/PII.** (lembrar: hash para correlação quando necessário.)

## 🔬 Behavior Change = Test First
- Antes de alterar código EXISTENTE: escreva um teste que CAPTURA o comportamento desejado.
- Se não há padrão/framework claro no repo → **PERGUNTE antes de inventar.**
